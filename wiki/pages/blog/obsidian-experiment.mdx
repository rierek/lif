## How an item looks

A real item from a throwaway store, made with `lif create 'Write the queue' -t task --parent <epic> -p high --tag docs`:

```markdown
---
# demo-fwep
title: Write the queue
status: todo
type: task
priority: high
tags:
    - docs
created_at: 2026-10-14T20:58:10Z
updated_at: 2026-10-14T20:58:10Z
parent: demo-0zvt
---
```

The file is `demo-fwep--write-the-queue.md`. The ID comes from the file name, not from the front matter. The first line `# demo-fwep` is only a YAML comment. Every field in the format is described in the [item file format](../../reference/item-file-format/).

Obsidian's documentation says properties are stored as YAML at the top of a note, in the form `name: value`, and that list values are written as `- value` lines. Both match this file. The documentation also lists `tags` as a property whose value must be a list, which is how Lif writes `tags`. It allows hyphens and letters in tags and treats them as case-insensitive. Lif writes lower-case, hyphenated tags.

## Setup to try

Lif's store is `.lif/` by default, a dot directory. Lif skips dot directories inside the store, and the Obsidian documentation does not say how Obsidian treats a dot folder in a vault. We avoid the question: use a store folder without a leading dot, set with `lif.path`.

```text
vault/
├── .lif.yml          lif.path: backlog
└── backlog/          the Lif store: one .md file per item
```

Steps:

1. `lif init`, then rename `.lif/` to `backlog/` and set `lif.path: backlog` in `.lif.yml`. `lif path` must print the new folder. See [Store management](../../overview/store-management/).
2. In Obsidian choose "Open folder as vault" and select the folder (as described in [Create a vault](https://help.obsidian.md/vault)). Obsidian adds its own `.obsidian/` folder there.
3. Open an item. Check whether the properties show at the top and which type Obsidian assigns to each.

The same layout with the vault one level higher, for example the whole workspace, is a variant. We did not decide between them.

## Bases: untested sketch

Obsidian's Bases core plugin shows files as table rows and properties as columns. Its documentation says a base is YAML in a `.base` file, that by default it includes every file in the vault, and that `filters` narrow it. A sketch built only from the documented syntax, not run:

```yaml
filters:
  and:
    - file.inFolder("backlog")
views:
  - type: table
    name: "All items"
    order:
      - file.name
      - status
      - type
      - priority
  - type: kanban
    name: "By status"
    groupBy:
      property: note.status
      direction: ASC
```

Whether a view like this works over Lif items is the point of the experiment. We make no statement about it.

## Validate after every edit

Obsidian does not know Lif's rules. After you edit items by hand, run `lif check`. Here we edited a file with a text tool instead of Obsidian, setting `status: doing`, which is not a status of the preset:

```console
$ lif check
...
  ✗ item demo-fwep carries unknown status 'doing'
...
1 issue found
$ echo $?
1
```

Renaming a file changes the item ID, because the ID is the part of the file name before `--`. We renamed `demo-fwep--write-the-queue.md` to `Write the queue.md`:

```console
$ lif list
TYPE  ID               TITLE
task  Write the queue  Write the queue
epic  demo-0zvt        Notes app
$ lif show demo-fwep
Error: item not found: demo-fwep
```

`lif check` reported a prefix inconsistency in that state, not a missing item. An editor that renames files, for example to follow a title, would break the ID and the `parent` links that point to it. Check whether Obsidian renames on title change: we did not run it.

## What to watch in a trial

- Does Obsidian rewrite a file when you only open it, or only when you edit a property?
- After an edit in Obsidian, does `git diff` show more than the changed value: the `# <id>` comment, key order, list indentation, the `Z` timestamps?
- Does Obsidian keep a key it does not know? Lif keeps unknown keys; see [item file format](../../reference/item-file-format/).
- Does `lif check` pass after the edit, and `lif list` show the same item ID as before?

If you try it, tell us what happened and we will update this post.

## Limits

- **Everything about Obsidian is untested.** The post cannot say whether it works.
- **Hand edits bypass the CLI.** `lif check` finds unknown status or priority, invalid tags, wrong parent rank, broken links and cycles. It does not find duplicate IDs or a file name that does not match the ID. See [Editing by hand](../../reference/item-file-format/#editing-by-hand).
- **Blocking links are stored on one side.** `lif check` does not report a difference between the two sides.
