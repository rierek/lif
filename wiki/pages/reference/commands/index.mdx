## Purpose
Hand-written introduction to the generated command pages: all commands at a glance, how they relate to their parents, and the shared flags and conventions that are not repeated on every command page.

## Audience
Everyone who looks for the right command or wants to know what holds for all commands (IDs, `--json`, exit codes). Agents that need to take in the whole command space.

### The lif command line
- Explains the two binaries: `lif` (CLI, TUI, GraphQL in process) and `lif-serve` (web server, single command `serve`).
- Names the number: `lif --help` lists 28 commands; 26 of them are defined in the repository, `completion` and `help` come from Cobra. Cobra's `help` has no page of its own (D57).

- Note: marker "plumbing" for `init`, `path`, `version`, `help`, `completion` (not meant for interactive typing); all others are user-facing.

### Global flags
- Table: `--config <path>` (path to the config file; without it the search goes upward for `.lif.yml`; an old `.beans.yml` is read when no `.lif.yml` exists).
- Table: `--lif-path <path>` (path to the store; beats config and `LIF_PATH`; an old `BEANS_PATH` is read when `LIF_PATH` is not set).
- Table: `-h, --help` (Cobra default, on every command).
- Links to `reference/configuration` (Store resolution) for the order flag, config, `LIF_PATH`, default directory, and to Store management (`overview/store-management`).
- Source: FACTS.md §1.0, §4.2

### Shared conventions
- Item ID: full ID or short ID without the configured prefix.
- `--json`: flag of most commands; not available on `graph` (uses `--format json`), `path`, `pick`, `prime`, `tui` and the Cobra commands; details on `reference/json-schemas`.
- Exit codes: 0 on success, 1 on error; errors are printed once, Cobra usage is suppressed; `lif check` returns 1 on at least one finding; no exit code 2.
- Commands without a store: `init`, `prime`, `version`, `tui`; all others load config and items before running, a missing store is an error.
- Aliases: `ls` (`list`), `rm` (`delete`), `new` and `c` (`create`), `query` (`graphql`), `u` (`update`).
- Several IDs: many write commands (`start`, `complete`, `scrap`, `update`, `tag`, `delete`) take several IDs; checks run for all IDs before the first write (confirmed for `update`, `complete`).
- Source: FACTS.md §1.0, §1.1 (per command: aliases, flags, Purpose), §6.11
