## Headline

The product is named Lif everywhere. Texts, release channels and JSON keys use `lif` and `item`. Legacy `beans` names still work as input.

## New commands and flags

- Release channels (releases, Homebrew cask, `install.sh`) point to `xRiErOS/lif`. `install.sh` reads `LIF_REPO`, `LIF_BIN_DIR` and `LIF_VERSION`.
- JSON output uses the key `item` or `items` instead of `bean` or `beans`. `check --json` reports `item_issues`.
- Lif reads the legacy `.beans.yml`, the `beans:` key, the `.beans/` store and `BEANS_PATH` beside the lif names. If both names exist at one level, Lif fails with an error that names both.
- Legacy worktree roots, `beans/` branches and `BEANS_WORKSPACE_PORT` keep working beside the lif forms.
- `lif check` reports legacy names.
- `lif roadmap` interleaves epic and feature containers by order, and sizes its columns by content.

## Fixes

- Detached worktrees are found under a symlinked root.
- `lif init` keeps legacy names.
- Binary names and build flags are renamed to lif.

## Upgrade notes

- The old JSON keys are gone, with no alias. Update scripts that read `bean`, `beans` or `item_id`-style keys.
- The `--beans-path` flag is removed without an alias. Use `--lif-path`.
- `lif init` creates only lif names.

## Limits

[1y6w] `lif init` replaces an existing `.lif.yml` or `.beans.yml` silently. See [Known limitations](../../known-limitations/).
