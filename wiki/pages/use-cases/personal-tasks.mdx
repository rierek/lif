## Set it up

Start with the preset `todo`. It has one type, `task`, and no hierarchy. Group with tags.

```sh
lif init --profile todo
lif create "Pay car insurance" --tag admin -p critical --set due=2026-11-01
lif next
lif start <id>
lif complete <id> --summary "Paid"
```

Priorities are `critical`, `high`, `normal`, `low` and `deferred`. `lif order` sets a manual order. `lif scrap <id> --reason "..."` drops a task you will not do. Item ID arguments also accept the ID without the prefix.

## Grow when you need structure

Items do not depend on the preset. A preset only writes the `types` table into `.lif.yml`. To add a hierarchy, replace that table with the one `lif init --profile simple` writes. The example store passed `lif check` after the swap. A milestone then holds tasks:

## What you get

- Plain files you can read, search and version.
- One status and one priority are enough for `lif next`. No extra tool.
- A path from a flat list to milestones without converting your tasks.

## Limits

- Lif has no typed due date. Store it as an extra key with `--set due=2026-11-01` and filter with `lif list --where due=2026-11-01`. Lif does not read it as a date.
- Lif has no recurring tasks and no reminders. Use a calendar for those, and create the task when it is due.
- After you add containers, `lif next` can return a milestone. Use `lif next -t task` `[g5dn]`.
