### Guided form: `-i`/`--interactive`

`lif create -i [title]` opens a guided form with four steps in this order: title, type, priority, parent. The form is drawn on the controlling terminal (`/dev/tty`), so stdout carries only the result: the `Created <id> <path>` line, or with `--json` the item exactly as `lif create --json` prints it.

- **Terminal requirement.** Without a terminal on stdin the command exits non-zero at once with a message naming the missing terminal and never waits for input, so agents and scripts are safe. `lif create` without `-i` never opens a form, on a terminal or not.
- **Pre-fill order.** A field takes its flag (title argument, `--type`, `--priority`, `--parent`, `--tag`, `--status`), else its config default (`lif.default_type`, `lif.default_priority`, `lif.default_tags`, `lif.default_status`), else stays empty. There is no parent default. Whatever you enter in the form overrides every pre-fill. An empty priority pre-selects `(none)`, and the item then carries no priority of its own, as with plain `lif create`.
- **Parent step.** It lists the valid parents for the type chosen in the form as a roadmap tree, one row per item, with a context panel for the highlighted row; press `/` to filter by ID fragment or title. A pre-filled `--parent` that is no valid parent for the chosen type is dropped. A type without a valid parent type offers only `(no parent)`.
- **Action menu.** After the parent step a menu offers, in this order: `go to body`, `create`, `create next`, `set tags`, `set blocked_by`, `set blocking`, `set status`. Under `--json` the menu has no `create next`, so one run prints exactly one JSON object. The cursor starts on `create`, so Enter writes the item at once. `go to body` opens an inline text field pre-filled with the body (`--body`); `Ctrl+E` opens `$EDITOR` on it and takes the saved text. `set tags` takes a comma separated list and rejects an invalid tag in place; new tags are allowed. `set blocked_by` and `set blocking` are filterable multiple choices (`/`) over the same items `--blocked-by` completes. `set status` picks among the configured statuses instead of `lif.default_status`. Each step starts with the current draft value and returns to the menu; `create` writes the draft with everything entered.
- **Capture a series: `create next`.** `create next` writes the item (one `Created` line, as `create`) and then shows a carry-over checklist with four entries: `type`, `priority`, `parent`, `tags`. The first checklist of a run has all four ticked; each later checklist starts with the entries you confirmed in the previous one. The choice lives only in memory for the run and is written nowhere. `/` filters the checklist, and `Esc` ends the filter without closing it. After the checklist a new form asks only for what you did not carry: always the title, the type and the priority when unticked, and the parent when parent or type is unticked (valid parents depend on the type). The body field opens right after the form, then the action menu follows. The title and body are always empty. An unticked field, and `status`, `blocked_by` and `blocking`, start as in the first form (flag, else config default, else empty). A carried parent that is no valid parent for a changed type is dropped. Each completed form writes one item and prints its `Created` line.
- **Cancel.** `Ctrl+C` at the menu or in any step writes nothing more. Before the run has written an item it exits non-zero with no stderr line. After `create next` has written at least one item, `Ctrl+C` in the checklist or in any step of a following form ends the run with exit code 0, with every completed item stored. `Esc` never cancels: in an active filter it ends filter entry.
- **Other flags.** `--prefix`, `--set`, `--unset`, `--order`, `--body`, `--body-file`, `--blocking` and `--blocked-by` keep their plain-create meaning. The form colours follow the configured `display.theme` flavour.

```
lif create -i "Fix login bug" --type bug
```
