### Configuration checks

Configuration checks cover: that `default_status` and `default_type` name entries that actually exist, that `default_priority` names a known priority and every `default_tags` entry is a valid tag, that every item on disk carries a type the current configuration still defines (a config edit or profile switch can leave items behind with a type nothing recognizes anymore), that every configured status and type `color` names a valid theme tone, and that the configured ID prefix (`lif.prefix`) matches what the item files on disk actually carry — archived items are excluded from that comparison, since a project can rename its live prefix without needing to touch history.

### Item file names

An item gets its ID from its file name. `lif check` also reads the `# <id>` comment on the first front matter line, which Lif writes with the ID it knows. When the two differ, the file was renamed by hand (or copied): the check reports the file name, both IDs and, when the recorded ID belongs to no loaded item, the links that now dangle. A file without that comment is not checked. `--fix` does not repair this finding. It also does not remove the links that dangle because of it: it prints each of them as `kept broken link`, they stay findings and the exit code stays 1, while every other broken link is removed as before. Rename the file back, or run `lif rename <id> <recorded-id>`, which changes the file name, the comment and the links together; the kept links then work again.
