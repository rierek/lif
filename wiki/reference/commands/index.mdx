## The lif command line

Lif ships two binaries. `lif` is the CLI; it also contains the [TUI](../tui/start-and-repositories/) and [GraphQL](../graphql/) in process. `lif-serve` is the [web server](../web-server/) with a single command, `serve`.

The root command is described as "A file-based issue tracker for AI-first workflows". `lif --help` lists 28 commands (Lif 0.14, 2026-10-14). 27 of them have a page here. Cobra's built-in `help` has no page. The four `completion` shells (bash, zsh, fish, powershell) share one page. Hidden commands, such as the `lif serve` placeholder, are not documented.

`init`, `path`, `version`, `help` and `completion` are plumbing: you rarely type them interactively. All other commands are user-facing.

## Command hierarchy

Every command sits one level below its parent. `lif` is the root, and the shells of `completion` sit below `completion`. The list is alphabetical, without categories, and shows one line of purpose per command. It is generated from the command tree and not edited by hand; each command page also links to its parent in "SEE ALSO".

## Global flags

| Flag | Meaning |
|---|---|
| `--config <path>` | Path to the config file. Without it Lif searches upward for `.lif.yml`. A legacy `.beans.yml` is read when no `.lif.yml` exists. |
| `--lif-path <path>` | Path to the store. Beats the config and `LIF_PATH`. A legacy `BEANS_PATH` is read when `LIF_PATH` is not set. |
| `-h`, `--help` | Help for the command (on every command). |

The order of flag, config and `LIF_PATH` is in [Configuration](../configuration/#store-resolution). The task-oriented view is [Store management](../../overview/store-management/).

## Shared conventions

- **Item ID:** the full ID, or the short ID without the configured prefix (`ix1n` for `f014j-ix1n`).
- **`--json`:** a flag of most commands. `graph` uses `--format json`. `path`, `pick`, `prime`, `tui` and the Cobra commands have no JSON output. Details: [JSON output](../json-output/).
- **Exit codes:** 0 on success, 1 on error. Errors print once and Cobra's usage text is suppressed. `lif check` returns 1 on at least one finding. Only `lif run` uses other codes: the exit code of the failing step, 128 plus the signal number for a step that a signal killed, and 2 for an error of Lif itself (unknown task, missing argument, cycle, invalid config). A step failure prints only `Error: task "<name>": step <n> of <total> failed (exit code <c>)`, without the `--help` pointer. See [Tasks](../configuration/#tasks).
- **Commands without a store:** `init`, `prime`, `version`, `tui` and `run`. All other commands load the config and the items first. A missing store is an error.
- **Several IDs:** `start`, `complete`, `scrap`, `update`, `tag` and `delete` take several IDs. These commands resolve all IDs, and `update` and `complete` also run their checks, before the first write. For `update` that covers the status policy, the parent and type rules and the `--blocking` and `--blocked-by` links, cycles included. An unknown ID, or the same item named twice (`item <id> named more than once`), fails with nothing written. After the writes begin, each item is written on its own, so a later failure such as an etag conflict leaves earlier items changed.
- **`update`:** needs at least one change flag (`--set` and `--unset` count). `--set` rejects reserved fields, for example `"status" is a reserved field; use --status instead`.
- **`show`:** `--json`, `--raw`, `--body-only` and `--etag-only` exclude each other and `--meta` and `--table`; `--meta --table` is allowed. `show --parent <id>` fails with `item has no children: <id>` when the item has no children.
- **`archive`:** moves items in an archive status to `archive/`. The reported count includes items already archived, so a second run reports the same number. There is no `unarchive` command: `update` leaves an archived item in `archive/`, and you move the file back by hand.
- **Display width** (`show`, `list`, `roadmap`, `milestones`): the width never exceeds the terminal width and never falls below 80. `--max-width` beats `display.max_width`, which beats 110. `--max-width 0` removes the cap; in the config use `-1`, because `0` there means 110.

## How these pages are generated

The command pages come from the command tree of the `lif` binary, built by the generator `cmd/lif-docgen`. Do not edit them by hand. The help texts contain no web links.
