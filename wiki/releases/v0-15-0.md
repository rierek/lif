## Headline

`lif create -i` opens a guided form for new items. `lif-serve` listens on `127.0.0.1` by default and asks for an access token beyond loopback. The `--json` output has generated JSON schemas. This release also fixes the findings of the documentation fact round: cycle detection, store integrity, `lif promote`, search help, the TUI and the CLI surface.

## Upgrade notes

:::caution[Breaking: lif-serve listens on 127.0.0.1 by default]
In 0.14 `lif-serve` listened on all interfaces. From 0.15 it listens on `127.0.0.1` only, so a browser on another machine, in Docker or on your LAN can no longer reach it.

- To serve beyond loopback, pass `--host <address>` (for example `--host 0.0.0.0`).
- Beyond loopback every request needs the access token that the server prints at startup. Open the printed `/?token=<token>` address once in the browser; scripts send `Authorization: Bearer <token>`.
- Beyond loopback the terminal is off. `--allow-remote-terminal` turns it on; the token is still required.
- `--cors-origin '*'` now only lets any page read answers. Changes, WebSockets and the terminal still need a listed origin.

There is no TLS: beyond loopback the token travels in clear text. Prefer the default address with an SSH tunnel or a VPN. See [Web server](../../reference/web-server/).
:::

Other changes that can affect scripts are listed in [Upgrading](../../overview/upgrading/#json-output-and-cli-behaviour-015):

- `lif init` stops with an error when a config exists; `lif init --force` replaces it.
- `show --json` returns the body without a leading newline, like `create --json`.
- A refused create returns `VALIDATION_ERROR` instead of `FILE_ERROR`; an I/O failure on update returns `FILE_ERROR` instead of `VALIDATION_ERROR`.
- An applied `lif rename --json` prints one document, the result.
- `lif check --json` reports a mixed-field cycle with `link_type` `blocking` and a subtree cycle with `blocking+parent`; `blocked_by` no longer appears.

## New commands and flags

- `lif create -i` opens a guided form: title, type, priority, parent from a roadmap tree, then body, tags, relations and status. "Create next" keeps a checklist of values to carry over.
- Config keys `lif.default_priority` and `lif.default_tags` for `lif create -i`.
- `lif promote --parent <id>` creates promoted items under that item. The artifact format is documented on the command page.
- `lif init --force` replaces an existing config.
- `lif --version` prints the same as `lif version`.
- `lif rename --prefix <new> --dry-run` lists every refusal, not only the first.
- `lif-serve --host`, `--allow-remote-terminal` and an access token beyond loopback.
- JSON schemas for every `--json` output under `schemas/`, generated with `just schemas`.

## Fixes

- Cycle detection treats `blocking` and `blocked_by` as one set of links, refuses a blocker inside or above the blocked item's subtree, and `lif check` prints each cycle from its smallest ID.
- `lif next` and `lif list --ready` leave out container items.
- A UTF-8 BOM, a `.nan` or `.inf` value and a hand-renamed item file are handled without data loss; `lif check` reports the rename.
- `--if-match` locks the item file, so two simultaneous updates cannot both win.
- `lif promote` checks every record before the first write and applies the default status.
- Search help and the GraphQL schema teach `+term` and `-term`; the unused persisted index is removed.
- The TUI uses the statuses, types, priorities and colors of `.lif.yml`, shows `↑↓` in the lobby footer and says `Really quit lif?`.
- `lif help`, `lif completion` and shell completion work outside a project; `create` and `update` help list the configured names.
- The `lif-serve` startup log names the real listen address.
- GitHub security alerts are fixed or dismissed with a reason, and Dependabot is configured; CI actions run on Node 24.
