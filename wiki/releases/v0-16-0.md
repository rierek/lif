## Headline

`lif run` runs named shell tasks from `.lif.yml` or `~/.lif/tasks.yml`. Hooks run a task by themselves when an item is created or changes, and a gate can refuse a change before it is written. `lif-serve` gets a light, dark and system theme, TLS, a persistent access token and proxy support. The web frontend moves to SvelteKit 3 and Vite 8.

## Upgrade notes

:::caution[Changed: lif-serve refuses agent sessions beyond loopback]
When `lif-serve` is reachable beyond this machine, it refuses agent sessions unless you pass `--allow-remote-agent`. The terminal still needs `--allow-remote-terminal`. See [Web server](../../reference/web-server/).
:::

Other changes that can affect scripts:

- Uppercase tags are rejected on write: `--tag URGENT` fails like a tag with a space. `lif update --remove-tag` still matches any case.
- A title with a control character is rejected on create and update, in the CLI and in GraphQL.
- A change that a gate blocks is an error with the code `POLICY_VIOLATION`, exit code 1, and no `Run '<command> --help' for usage.` line. The GraphQL error carries the same code in `errors[0].extensions.code`.
- `lif run` exits with the exit code of the failing step, with 128+n when a signal killed the step (143 for SIGTERM), and with 2 for an error of Lif itself: unknown task, missing argument, unknown flag, dependency cycle, invalid task config. A failing step prints only `Error: task "<name>": step <n> of <total> failed (exit code <c>)`.
- Every task step, also one that a hook or gate runs, runs with `sh -ec`: the first failing command stops the step, also in a multi-line step. Append `|| true` to a command whose failure you want to ignore.
- `lif-serve` accepts changes, WebSocket upgrades and the terminal only from its own origin by default; a page on another local port gets 403. A dev server on another port needs `--cors-origin`, for example `--cors-origin http://localhost:5173`. `--cors-origin '*'` now only sets the CORS header and no longer lets other local ports change items or open the terminal. See [Upgrading](../../overview/upgrading/).
- New IDs skip any ID that a loaded item or a file already uses. `lif check` reports an ID that several files carry.
- A task or hook in `.lif.yml` that is invalid makes every lif command in that project fail with the config error, not only `lif run`.

## New commands and flags

- `lif run` lists tasks. `lif run <task> [args...]` runs one. A task has `desc`, `args`, `deps` and `steps`, and lives in the project `.lif.yml` or in the global `~/.lif/tasks.yml`. A project task replaces a global task of the same name; `lif run -g <task>` runs the global one and resolves its dependencies globally. A step gets `LIF`, `LIF_ROOT`, `LIF_TASK` and `LIF_TASK_ORIGIN`, and `LIF_PATH` when a store path is set. SIGINT, SIGTERM and SIGHUP go to the step; `lif run` waits and returns the step's exit code, or 128+n when a signal killed it. See [Automation](../../features/automation/#tasks).
- `hooks:` in `.lif.yml` or `~/.lif/tasks.yml`. A hook has `event` (`created`, `updated`), the filters `changed`, `tags_added`, `tags_removed`, `from`, `to`, `type` and `tags`, the task in `run`, the item fields in `args`, and `timeout` in seconds (default 60, `0` for no limit). `stage: before` makes a hook a gate with an optional fixed `message`. A gate fails closed. A gate matches `type` and `tags` on the state before and after the change. See [Hooks](../../reference/configuration/#hooks).
- `lif hooks` lists every hook and gate and whether the project hooks run. `--steps` prints the steps that the hooks can run.
- `lif hooks allow` and `lif hooks deny` record and withdraw the trust for the hooks and tasks of a project. Project hooks run only after `lif hooks allow`; global hooks always run. Trust is keyed per repository, also for bare layouts. A running `lif-serve` treats a `.lif.yml` that changed on disk as not allowed. `allow` and `deny` repair a trust file that does not parse.
- `LIF_NO_HOOKS` skips after hooks and gates. `LIF_HOOK_DEPTH` stops a chain of `lif` calls from hooks after 3 levels. A task that a hook starts gets `LIF_NO_HOOKS=1`, so hooks do not chain.
- A hook or gate task keeps at most 64 KiB of output, and a blocked gate reports at most 8 KiB. An after hook that fails prints `warning: hook "<name>" (task "<task>"): <error>` and the change stays.
- `lif-serve --allow-remote-agent`, `--require-token`, `--public-url`, `--token-file` (or `LIF_SERVE_TOKEN`), `--tls-cert` and `--tls-key`, and `--host tailscale`, which binds the tailnet address. See [Remote access](../../reference/remote-access/).
- `lif-serve` serves the web UI under a sub-path when a proxy strips the prefix. No setting is needed. It fails loudly when it embeds no frontend build.
- The web UI has a light, dark and system theme switch, a palette derived from Catppuccin and `display.theme`, and it applies the statuses, types, priorities and colors of `.lif.yml`. Hard-coded colors are replaced by theme tokens.
- Service files and a remote-access guide for `lif-serve` are in the wiki.

## Fixes

- Hooks run in `lif-serve` too: a write through GraphQL fires the matching hooks and gates, and `lif-serve` returns the item as an after hook left it. A refused write shows on the status buttons and on drag in the web UI.
- A write checks its own ETag and retries when it is stale. Stale project gates block until `lif-serve` restarts.
- A hook that changes `id`, `slug`, `path` or `body` is rejected in `changed:`; a task step with `!!binary` or bidi control characters is rejected, and control characters in config text are dropped.
- A task runner forwards signals and kills the process group of a step. A hook or gate task has a timeout and an output cap.
- `lif hooks` lists a global hook while the project is not allowed, and a project hook cannot replace a global gate.
- Frontend dependencies: SvelteKit 3, Vite 8, vitest 5, TypeScript 6, ESLint 10, GraphQL 17, shiki 4 and marked 18. The `$lib` alias becomes `#lib`. Dependabot holds TypeScript 7 back and splits the frontend group by update type.
- The nix flake hashes are refreshed for 0.16.0, and CI and the release check them.

## Limits

Details are in [Automation](../../features/automation/), [Configuration](../../reference/configuration/#hooks) and [Known limitations](../../known-limitations/). These limits are documented, not fixed:

- `worktree.setup` and `worktree.run` have no trust check: `lif-serve` runs them with `sh -c` when you create a worktree or start a run in the web UI. Read them in a cloned repository first.
- A gate does not guard creation (`lif create -s completed`, `createItem`), and it does not run with `--config` or `--lif-path` from another directory. A hook sees only changes that go through Lif.
- `lif run` has no `--json`.
- Project gates run only while the project is allowed. An edit of the hooks or tasks in `.lif.yml`, also by an agent and also in a fresh clone or worktree, takes the allow back. Until the next `lif hooks allow`, a watched change succeeds with exit code 0 and only a warning on stderr; `--json` output carries no warning.
- Hooks run in the environment of the process that starts them, and a gate task that prints its environment shows it to every client of `lif-serve`.
- TLS for `lif-serve` is opt-in [8h4v] (`--tls-cert` and `--tls-key`), and `display.theme` has no effect in the TUI [179g].
