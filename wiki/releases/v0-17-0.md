## Headline

`lif tui` is rebuilt. It starts on the roadmap, drawn like `lif roadmap`, and you open the filter bar and the detail pane with `v`. `tab` only moves focus, through the list, the filter fields and the detail boxes. The key map is one scheme: capital letters open views, lower-case letters change the selected item. The TUI reads and writes in its own process, follows `display.theme`, and runs tasks from the new `tui.actions` block.

## Upgrade notes

:::caution[Changed: TUI keys moved]
Several TUI keys have a new meaning. The old keys do nothing now, or do something else. Press `?` for the keys of your version. See [Key bindings](../../reference/tui/key-bindings/).

| Before | Now |
|---|---|
| `o` type, `u` priority | `t` type, `p` priority |
| `t` tags | `g` tags |
| `r` relations picker | `b` Relations |
| `b` Backlog | `R` Ready |
| `p` repository picker | `P` repository picker |
| `G` nested or flat | `M` roadmap, `L` flat list |
| `v` fullscreen | `v` and `shift+v` cycle the layouts |
| `ctrl+left`, `ctrl+right` history | removed |
| `[`, `]` history | `[` and `]` now jump to the previous or next sibling in the roadmap |
| `1` to `9` jump to a section | removed |
| `LIF_TUI_BOXFORM=0` classic layout | removed; the box form is the only form |
:::

Other changes that can affect how you work in the TUI:

- The start view is the roadmap at full width. It has no filter bar and no detail pane. `v` goes to the next layout and `shift+v` to the previous one: Roadmap, Roadmap + filter, Roadmap + filter + details, Details. See [Views](../../reference/tui/views/#layouts).
- `tab` no longer opens the detail pane, and `shift+tab` no longer opens it either. Both only move focus and never change the layout. In layout Roadmap they do nothing. See [Focus ring](../../reference/tui/views/#focus-ring).
- The tree is the roadmap: milestones start collapsed, and the roots `Unscheduled` and `Not on roadmap` come last. `Not on roadmap` replaces `(orphaned)`. Every level is sorted like `lif roadmap`. The tree and flat lists have no column header.
- In the roadmap, `zo` and `zc` open or close the cursor item with all its children, and `zR` and `zM` open or close every item. See [Key bindings](../../reference/tui/key-bindings/#navigation).
- A search in the roadmap opens the ancestors of every hit and mutes the rows without a hit. The cursor only moves between hits, and clearing the search restores the previous open and closed state.
- The Backlog view is now the Ready view. It lists what `lif list --ready` lists. `esc` clears a search or filter and then returns to the roadmap.
- `f` focuses the Type field of the filter bar. The filter overlay is gone. `X` clears Type, Status, Priority and Tags. Archive is a view switch, not a filter, so `X` leaves it as it is.
- In the lobby, typing no longer filters. `/` opens the filter. `i` and `k` move like the arrow keys. `q` asks `Quit?` there too. `esc` twice leaves the lobby.
- `ctrl+c` quits at once from every state: lists, forms, menus, dialogs and the lobby. It no longer closes the command palette. `q` still asks first. In every dialog `y` confirms and `n` cancels.
- Command palette entries are named `verb: action`. For example `go to tags` is `view: tags`, `go to settings` is `view: settings`, `register project` is `register: project` and `set title` is `set: title`. `:` opens the palette like `K`.
- The TUI follows `display.theme`, including the light `latte`, and the statuses, types, priorities, colors and short letters of `.lif.yml`. It was a fixed dark palette before.
- `lif tui` reads `.lif.yml` and honors `--config` and `--lif-path` for the repository it opens.

## New commands and flags

- `tui.actions` in `.lif.yml` exposes tasks in the TUI. An action has `task`, and optionally `key`, `label` and `statuses`. It shows up as the palette entry `run: <label>` and as a key. A task with one argument gets the ID of the focused item. Every step also gets `LIF_ITEM_ID` and `LIF_PATH`. The output and the exit code show in an overlay. See [TUI actions](../../reference/configuration/tasks/).
- A bad action is dropped and the TUI shows a warning: an unknown task, a key with more than one character, or a key that the TUI already uses.
- The layouts `v` and `shift+v`, the focus ring and the Ready view `R`. Ready uses the same layouts. `S` cycles its sort.
- The roadmap in the TUI renders like `lif roadmap`: type and status words, wrapped titles, the ID on the right, tree lines and colors. An item can use several lines, and the cursor, the mouse and scrolling work on the whole item. The flat list `L` and Ready `R` show the same rows without tree lines. The columns do not move when a node opens or closes. Beside the detail pane the rows stay compact.
- The filter fields Type, Status, Priority, Tags and Archive are focus targets. `←` and `→` move between them. `enter`, `space` or `↓` open the value menu, and the list filters as you toggle values. A click on a field focuses it and opens its menu.
- The help (`?`) has a search field for keys, descriptions and groups, a Views section that describes every view and layout, and scrolling. See [Help](../../reference/tui/key-bindings/#help).
- `open: documentation` in the command palette opens the TUI reference in your browser. When no opener exists, a toast shows the URL.
- The footer lists only the keys that act in the current state.
- In the roadmap tree the footer shows `[ ]`, `zo zc` and `zR zM` at the right edge when the terminal is wide enough. The left list does not change.

## Fixes

- The TUI no longer starts `lif` for each read and write. It uses the same store, hooks and gates as the CLI in its own process. A blocked gate shows its hook name and message, and the output of a failed after hook shows as a warning.
- `tab` no longer traps you in the detail pane. `tab` and `shift+tab` walk the focus ring forward and back, and `esc` still returns to the list.
- The Go packages `pkg/roadmap` (roadmap builders) and `pkg/itemgraph` (`ApplyReadyFilter`) now hold code that `lif roadmap`, `lif list --ready` and the TUI share. The output of `lif roadmap`, `lif check` and `lif path` is unchanged. `schemas/roadmap.schema.json` renames its internal definitions (for example `roadmapData` is `Data`); the JSON that it describes is the same.

## Limits

Details are in [Configuration](../../reference/configuration/tasks/) and [Known limitations](../../known-limitations/). These limits are documented, not fixed:

- A task that a `tui.actions` entry runs has no trust check, like `lif run`. It runs in the TUI process with empty stdin, so a task that reads input fails. A task with more than one argument is an error. Read the `tasks:` of a cloned repository before you press a key of an action.
- `display.max_width` has no effect in the TUI. It fills the terminal.
- The `display.theme` limit [179g] is fixed in 0.17.
