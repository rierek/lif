## Headline

This release adds a Waves view to the TUI, a per-type `parents` setting, a check for redundant blocking edges and interactive search in the shell. Without the `parents` field in your configuration, the rank rule applies as before. No file format changes.

## New

- TUI: the Waves view shows the children of a root item as cards in columns by `blocked_by`, with edge routing, focus, the critical path and edge editing with `b`. Open it with `W` or the palette entry `view: waves`. See [Views](../../reference/tui/views/).
- Configuration: the optional `parents` list per type names the types an item may have as parent. It is checked when the configuration loads, enforced on every write path (CLI, TUI, GraphQL, promote) and reported by `lif check`. See [Types and statuses](../../reference/configuration/types-and-statuses/).
- `lif check` reports redundant `blocked_by` edges as a warning (`--strict` exits with 1). `--fix` removes them and names the path that makes each edge redundant. `lif graph --reduce` prints the reduced graph. See [`lif check`](../../reference/commands/lif-check/) and [`lif graph`](../../reference/commands/lif-graph/).
- `lif list -i` and `lif roadmap -i` search, select and show items in the shell. See [Interactive shell](../../features/interactive-shell/).
- TUI: search in the flat list groups hits by the matched field (item, parent, children, relations, title or ID, body, full text). A search by item ID shows the item and its relatives.
- TUI: `j` and `l` page the detail body while the detail pane has focus. Paging keys appear in the `?` help.
- TUI: yank variants `yy`, `ym` and `yt`. See [Key bindings](../../reference/tui/key-bindings/).

## Fixes

- TUI: under `Not on roadmap`, an item whose parent is also there now nests under it. Before, all these items showed flat. Parent cycles stay flat.
- TUI: the breadcrumb of the roadmap view reads `Roadmap` instead of `Browse`.
- The web board drag no longer uses hardcoded parent types.
