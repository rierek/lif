Example: a thesis with two chapters. The section "Sampling" waits for an ethics approval letter. Open questions hang under the section they belong to.

## Set it up

Replace the software types with four of your own. A type without `rank` gets rank 4. A child needs a higher rank than its parent.

```yaml title=".lif.yml"
types_exclusive: true
types:
  - name: chapter
    rank: 1
  - name: section
    rank: 2
  - name: source
    rank: 4
  - name: question
    rank: 4
```

`lif check` passed on this table. See [Configuration](../../reference/configuration/). Then build the outline and mark what waits:

```sh
lif create "Methods" -t chapter
lif create "Sampling" -t section --parent <chapter-id> --tag methods
lif create "Ethics approval letter" -t source --parent <chapter-id>
lif update <sampling-id> --blocked-by <letter-id>
```

Place the blocker outside the item it blocks. Lif treats a blocked parent as blocking its children, so a blocker below it never frees it. `lif check` does not warn about this ([o8bs]).

`lif next --tag methods` names the next piece of work. `lif order <id> --after <id>` sets the order of sections. Put working notes in the item body.

## What you get

- Text and planning live side by side, and Git tracks both.
- A percentage per chapter and a list of what waits for a source.
- The same commands as in a software project, with your vocabulary.

## Limits

- Lif does not manage citations or a bibliography and does not assemble or export text. Keep references in your reference manager. Store its key on the source item with `--set cite_key=<key>`.
- `lif roadmap` worked with these types: in this example it printed `Chapter: Methods` and `Section: Sampling` as headings with the open question below. The source placed directly under the chapter appeared under `Miscellaneous`. Completed items did not appear.
